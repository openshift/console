# OpenShift Console 5.1 Release Notes

This release contains no runtime breaking changes. Existing plugins built for Console 4.23 / 5.0
remain fully compatible without modification when loaded in Console 5.1.

## Changes to shared modules and API

- Added `react-dom` and `react/jsx-runtime` to Console provided shared modules. This ensures that
  helpers such as `createPortal` and the new JSX transform are reused consistently in all Console
  plugins. Plugins must avoid calling `createRoot` and `render` and let Console manage rendering.
- Deprecated the `redux`, `react-redux`, and `redux-thunk` shared modules to prevent plugins from
  accessing Console's root state.

## Changes to the Redux store

> [!NOTE]
> Plugins must not access Console-owned Redux state directly. Console exposes the Redux store only
> so that plugins can create and manage their own slices. Plugins that follow this rule are
> unaffected.

The Console-owned slices of the Redux store (such as `core`, `features`, `dashboards`, `UI`,
`observe`, and `k8s`) no longer use [Immutable.js]; they are plain JavaScript objects instead of
`Immutable.Map` and `Immutable.List` instances. As a result, Immutable.js APIs such as `.get()` and
`.getIn()` do not work on them.

## Changes to Content Security Policy (CSP)

The default `script-src` CSP directive no longer includes `'unsafe-eval'`. CSP remains in
report-only mode by default. Plugins that use `eval()` or `new Function()`, and plugins built in
eval-based development mode, continue to run but trigger `script-src` violation reports. Check these
reports and remove runtime code evaluation from your plugin before Console enforces CSP. CSP
enforcement is targeted for OpenShift Container Platform 5.2. The rollout strategy, including
whether enforcement is enabled by default, is still under discussion.

The default `img-src` CSP directive includes `blob:` in addition to `'self'`, `https:`, and `data:`.
Plugins can load images from blob URLs without extending the `img-src` directive. If your plugin
already adds `blob:` to `img-src`, that entry is redundant, but keep it to support older Console
versions that do not include `blob:` by default.

## Changes to plugin API

### New `ConsoleDataView` component

`ConsoleDataView` is a table component for displaying, filtering, sorting, and paginating a list of
items, such as Kubernetes resources. It is based on the PatternFly [Data view] component and
includes built-in name and label filters, column management, and optional row selection.

`ConsoleDataView` requires an `id` prop that accepts a Kubernetes model, a group/version/kind (GVK),
or a string. Set a column's `type` to `name`, `namespace`, `actions`, `selection`, or `sticky` to
apply built-in header and cell behavior, such as default titles, sorting, and visibility in column
management.

Pass `selection.getItemId` to add a selection column; Console creates and manages the column
automatically. Use `selection.isSelectable` to exclude individual rows from selection, and
`selection.getBulkActions` to return table-specific bulk actions for the selected items.

Custom filters extend `ResourceFilters` with string or string-array fields. Declare every custom key
in `initialFilters`, render the filter controls in `additionalFilterNodes`, and implement the
matching logic in `matchesAdditionalFilters`.

To contribute bulk actions from a `console.action/resource-provider` extension, add `bulkProvider`
alongside the existing single-resource `provider`:

```json
{
  "type": "console.action/resource-provider",
  "properties": {
    "model": { "version": "v1", "kind": "Node" },
    "provider": { "$codeRef": "nodeActions.useNodeActions" },
    "bulkProvider": { "$codeRef": "nodeActions.useNodeBulkActionsProvider" }
  }
}
```

The `bulkProvider` hook returns `[Action[], loaded, error]` like other action providers. Console
does not automatically reuse single-resource action callbacks for bulk selections.

For the full component, column, and cell options, see the [`ConsoleDataView` API documentation].

#### New `console.dataview/table-column` extension

Plugins can add columns to a `ConsoleDataView` by setting the `console.dataview/table-column`
extension's `table` property to the resolved `id` of the target table (the string form of its `id`
prop). The `columnData` property is either a code reference to a `ConsoleDataViewExtensionColumn` or
an inline `ConsoleDataViewInlineColumn` definition containing JSON-compatible options. The
`getCellContent` property is a code reference to a `GetDataViewCell` function that returns one cell
per row.

Extension columns are hidden by default; set `columnData.defaultVisible` to `true` to show the
column initially. Users can show hidden columns in column management.

Use `insertBefore` or `insertAfter` with an anchor (the `id` of an existing column) to position the
new column. Column IDs must be unique within the table; prefix them with your plugin name.

```json
{
  "type": "console.dataview/table-column",
  "properties": {
    "table": {
      "group": "apps",
      "version": "v1",
      "kind": "Deployment"
    },
    "columnData": { "$codeRef": "columns.readyColumn" },
    "getCellContent": { "$codeRef": "columns.getReadyCells" },
    "insertAfter": "name"
  }
}
```

#### Migration from `VirtualizedTable`

`VirtualizedTable` is deprecated and might be removed in a future release. Build new tables with
`ConsoleDataView` or directly with the PatternFly Data view component.

Before this update, adding a column to a resource list often required replacing the entire list page
because `VirtualizedTable` did not support column contributions.

When the target list uses `ConsoleDataView`, add columns with the `console.dataview/table-column`
extension. If the list displays actions for the resource model, use
`console.action/resource-provider` to contribute additional actions.

These extensions preserve the existing list page and its filtering, sorting, and navigation
behavior. Replace the list page when the extensions cannot provide the required behavior.

### Prometheus support for inventory items

The `console.dashboards/overview/inventory/item` and `console.dashboards/project/overview/item`
extensions accept an optional `prometheus` code reference that supplies queries for aggregate counts
and statuses. The Kubernetes watch configuration is still required; Console uses the Prometheus
queries when monitoring is enabled and falls back to the watch when it is disabled.

When a query fails, the inventory item displays **Not available**. Console continues to retry the
query rather than starting a watch. Existing extensions without Prometheus configuration continue to
use Kubernetes watches.

Counts reflect sampled metrics and can temporarily differ from those shown in resource lists. On
clusters that use the minimal metrics collection profile, inventory items fall back to Kubernetes
watches because that profile does not collect the required metrics.

### New `definitionFor` function

The `definitionFor` function looks up the OpenAPI schema definition for a Kubernetes model. It
returns `null` if the schema has not finished loading.

```ts
const definition = definitionFor(PodModel);
const specDescription = definition?.properties?.spec?.description;
```

### Tab badges and default tab ordering

The `console.tab` extension accepts an optional `badge` code reference. Console renders the
referenced component next to the tab label. Use a badge to show a lightweight status indicator or to
provide an informational popover.

Console treats contributed tabs with an empty `href` as default tabs and orders them first. The
remaining tabs are sorted alphabetically.
