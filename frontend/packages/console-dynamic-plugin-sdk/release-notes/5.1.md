# OpenShift Console 5.1 Release Notes

## Changes to the Redux store

> [!NOTE]
> Plugins must not access or read Console-owned Redux state directly. Console exposes the Redux store only so
> that plugins can create and manage their own section of the store.

The Console-owned slices of the Redux store (such as `core`, `features`, `dashboards`, `UI`, `observe`, and `k8s`)
no longer use [Immutable.js](https://immutable-js.com/). These state slices are plain JavaScript objects instead
of `Immutable.Map` and `Immutable.List` instances. Because these slices are plain JavaScript objects, Immutable.js
APIs such as `.get()` and `.getIn()` no longer work on them.

## Changes to Content Security Policy (CSP)

The default `script-src` directive no longer includes `'unsafe-eval'`. CSP remains in report-only mode,
so plugins that use `eval()`, `new Function()`, or eval-based development builds continue to run but produce
`script-src` violation reports. Plugin authors should check these reports and remove runtime code evaluation
before CSP is enforced.

## Changes to plugin API

### Optional tab badges and ordering

`console.tab` accepts an optional `badge` code reference. Console renders the referenced component beside
the tab label, which is useful for informational popovers and lightweight status indicators.
Contributed tabs with an empty `href` are treated as default tabs and are ordered before other contributed
tabs; the remaining tabs continue to be ordered alphabetically.

### New `ConsoleDataView` component

`ConsoleDataView` is a table component for displaying, filtering, sorting, and paginating a list of resources,
based on PatternFly's [Data view](https://www.patternfly.org/extensions/data-view/overview). It includes
built-in name and label filters, column management, and optional row selection.
Every `ConsoleDataView` requires an `id`, which accepts a Kubernetes model,
group/version/kind, or string. Console derives column management from `columns` and always
provides the column management action. The preference ID is derived from `id`.
Models and GVKs resolve to `group~version~kind` for column management, extension matching, and saved widths.

`VirtualizedTable` is deprecated and will be removed in a future release. New list pages should use
`ConsoleDataView` or PatternFly's Data view directly instead.

Set `ConsoleDataViewColumn.type` to `name`, `namespace`, `actions`, `selection`, or `sticky` to apply the
corresponding header and row cell props. Props supplied by the column or row cell take precedence.
Actions and selection columns always remain visible. Other columns follow visibility defaults and
saved preferences even when their titles are empty. Only an actions-role column receives the
implicit accessible header label `Actions`; give other blank headers an accessible label through
`props['aria-label']` or `props.screenReaderText`. Name-role columns are untoggleable in column
management regardless of their IDs; an ID of `name` alone does not lock a column.
Extension columns are placed before the actions-role column by default, regardless of its ID.
Name and namespace headers and row cells default to `modifier: 'nowrap'`. Override the header
modifier through the column's `props` and the body modifier through each row cell's `props`;
these overrides apply independently and can use `wrap`, `breakWord`, or `truncate`.
Name and namespace columns default to translated `Name` and `Namespace` titles and sort by
`metadata.name` and `metadata.namespace`, respectively. Every column still requires an `id`.
Explicit titles and sort paths or functions override these defaults; set `sort: false` to
disable sorting. Custom row shapes should override the metadata paths. Other column types
have an empty title and no sorting by default, so action columns can omit `title`.
When an `actions` row cell is omitted or has no `cell`, Console shows the resource actions from
`console.action/resource-provider` for Kubernetes resource rows. Set `cell: null` to leave the
cell empty. Rows that are not Kubernetes resources do not get a default kebab.
Set `type: 'namespace'` on columns that show a namespace. These columns are hidden while
viewing a single project and follow saved visibility preferences in All projects. Their IDs
can be any unique string; an ID of `namespace` alone does not give a column namespace behavior.
Set `showNamespaceOverride` to keep namespace-type columns visible regardless of the active
project or saved visibility preferences.

`getDataViewRows` returns one `ConsoleDataViewRow` per item. Each row contains typed
`ConsoleDataViewCell` objects with an `id` matching the column. Cells may be returned in any
order: Console aligns them by ID, ignores unknown IDs, and renders omitted cells empty
(except the default resource actions described above). Return at most one cell per column ID.
The callback receives only active built-in columns; Console supplies selection and extension
cells separately.

Default sorting uses the first active column. When a checkbox column is present, it uses the
first sortable column instead, or leaves the data order unchanged if none are sortable.
An explicit `defaultSortColumnId` still takes precedence over this fallback. Checkbox tables
also ignore and remove URL sort targets that are not sortable. Tables without a checkbox column
keep their existing first-column fallback and URL sort behavior.

Name columns also receive a `data-test` value based on each row's name and shift automatically
when selection is enabled. For rows without Kubernetes metadata, use `getObjectMetadata`
to supply the name. Pass `selection.getItemId` to add a checkbox column and manage selection automatically.
Use `selection.isSelectable` to exclude individual rows, and `selection.getBulkActions` to return
table-specific bulk actions as `Action[]` for Console to render in a menu. Console also includes
actions from the selected model's opted-in resource bulk providers. An empty array hides the menu
only when no matching bulk provider supplies actions.
The action callback receives only selected items matching the current filters; selection persists
across pages and built-in filters, and is cleared for items that leave `data`.

Custom filters extend `ResourceFilters` with string or string-array fields. Declare every
custom key in `initialFilters`, using `''` or `[]` for inactive filters, so Console includes
it in URL synchronization and clearing. Boolean, numeric, and object values are not supported.
String values use a single URL parameter; array values use repeated parameters with the same
key. For example, `status: ['Running', 'Pending']` becomes
`?status=Running&status=Pending`.

```tsx
interface PodFilters extends ResourceFilters {
  status: string[];
}

// Pass this initial state along with additionalFilterNodes and matchesAdditionalFilters.
const initialFilters: PodFilters = { status: [] };
```

To opt in actions from a `console.action/resource-provider`, add `bulkProvider` alongside its
existing single-resource `provider`:

```json
{
  "type": "console.action/resource-provider",
  "properties": {
    "model": { "version": "v1", "kind": "Node" },
    "provider": { "$codeRef": "nodeActions.useNodeActions" },
    "bulkProvider": { "$codeRef": "nodeActions.useNodeBulkActionsProvider" }
  }
}
```

The bulk hook receives `matchingSelectedResources`, `getResourceId`, `clearSelection`, and `deselect`, and returns
`[Action[], loaded, error]` like other action providers. It returns only actions safe for the whole
selection; single-resource action callbacks are never reused automatically. Console calls it only
for a nonempty selection of Kubernetes resources of one model. The resources match the current
filters, while `clearSelection` clears all selected rows, including those hidden by filters. The
bulk hook is responsible for checking whether its action applies to, and is allowed for, the full
selection.

Bulk menus support `Action.path`, including `$top`, `$bottom`, and contributed
`console.action/group` sections and nested submenus. Ordering applies within each menu level.
`console.action/filter` extensions whose `contextId` matches the selected model receive
each matching selected resource individually, with the action being considered. Every resource
must pass at least one matching filter for the action to remain visible. No model filters are
applied to generic or mixed-model table selections. Filtering does not replace the bulk
provider's responsibility to check access for the whole selection.

By default, `ConsoleDataView` makes columns with a title resizable, saves their widths, and shows
a reset action. This includes extension columns. Set `isResizable={false}` on the table to disable
resizing. Widths are keyed by the resolved `id` and column ID. Set a column's `tooltip` to show a
help tooltip beside its header. Console owns header content, sorting, selection, and the
responsive label, so column props do not expose `cell`, `children`, `sort`, `select`, or
`dataLabel`. Set help content through `tooltip`; `props.info` configures its presentation.

#### Example usage

```tsx
const getDataViewRows: GetDataViewRows<PodDisruptionBudgetKind> = (data, columns) =>
  data.map(({ obj: pdb }) => {
    const resourceKind = referenceForModel(PodDisruptionBudgetModel);
    return columns.map(({ id }) =>
      id === 'actions'
        ? { id }
        : {
            id,
            cell: (
              <ResourceLink
                kind={resourceKind}
                name={pdb.metadata.name}
                namespace={pdb.metadata.namespace}
              />
            ),
          },
    );
  });

const PDBList: React.FC<Props> = ({ data, loaded }) => {
  const columns = React.useMemo<ConsoleDataViewColumn<PodDisruptionBudgetKind>[]>(
    () => [
      {
        id: 'name',
        type: 'name',
        title: 'Name',
        sort: 'metadata.name',
      },
      { id: 'actions', type: 'actions' },
    ],
    [],
  );

  return (
    <ConsoleDataView<PodDisruptionBudgetKind>
      label="PodDisruptionBudgets"
      data={data}
      loaded={loaded}
      columns={columns}
      getDataViewRows={getDataViewRows}
      id={PodDisruptionBudgetModel}
      selection={{
        getItemId: (pdb) => `${pdb.metadata.namespace}/${pdb.metadata.name}`,
        getBulkActions: ({ matchingSelectedItems, clearSelection }) => [
          {
            id: 'clear-selection',
            label: 'Clear selection',
            disabled: matchingSelectedItems.length === 0,
            cta: clearSelection,
          },
        ],
      }}
    />
  );
};
```

### New `console.dataview/table-column` extension

Plugins can add columns to a `ConsoleDataView` table by setting the extension's
`table` to the table's resolved `id`. The extension supplies code references for
a `ConsoleDataViewExtensionColumn` and a `GetDataViewCell` function. Alternatively,
`columnData` can be an inline `ConsoleDataViewInlineColumn` definition containing JSON-compatible
options. Use a code reference for sort functions, React tooltips, or additional header props
and resize callbacks.
The function receives the current page of rows and returns one cell per row. Extension columns
are hidden by default; set `columnData.defaultVisible` to `true` to show a column initially.
Users can select hidden columns in column management. Built-in columns default to visible;
set their `defaultVisible` to `false` to hide them initially. Saved column preferences take
precedence over these defaults.

Use `insertBefore` or `insertAfter` with a column ID to choose a position. `insertBefore` wins
when both anchors exist. Columns with the same anchor are ordered by plugin name, then column ID.
Columns without a valid anchor appear before the actions column, or at the end of a table that
has no actions column. Column IDs must be unique; prefix them with your plugin name.

```json
{
  "type": "console.dataview/table-column",
  "properties": {
    "table": {
      "group": "apps",
      "version": "v1",
      "kind": "Deployment"
    },
    "columnData": { "$codeRef": "columns.readyColumn" },
    "getCellContent": { "$codeRef": "columns.getReadyCells" },
    "insertAfter": "name"
  }
}
```

### New `definitionFor` function

`definitionFor` looks up the OpenAPI (Swagger) schema definition for a Kubernetes model. It returns `null` if
the OpenAPI schema has not finished loading, so plugins should check the result before reading its properties.

```ts
const definition = definitionFor(PodModel);
const specDescription = definition?.properties?.spec?.description;
```

## Migrating from `VirtualizedTable`

Plugins have often replaced an entire resource list table built with `VirtualizedTable` to add
columns because the table did not support column contributions. When the target list uses
`ConsoleDataView`, prefer `console.dataview/table-column` to add columns. Set its
`table` to the table's identifier. Use `console.action/resource-provider` to add
actions where the list displays actions for the resource model. These extensions preserve the
existing list page and its filtering, sorting, and navigation behavior. Replace the list page
when the extensions cannot provide the required behavior.
